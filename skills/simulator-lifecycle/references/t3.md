# T3 device routing and recovery

Use the host's live device contract as the authority for supported operations.
The [T3 device contract](https://github.com/pingdotgg/t3code/blob/c71ca063dfcd8c2e3dcb2bd92adbb2180cbbece3/apps/server/src/mcp/toolkits/device/handlers.ts#L28)
is the source baseline; inspect live tools for the installed contract.

## Acquire and drive

Use `device_list`, then `device_open`, so the user can watch the device. Keep the
exact `agent-device` launcher, host configuration and session flags it returns
on every command. Prefer current snapshot refs. Report an unavailable platform.

Confirm that the host's documented SimLock integration acquires and drives the
same underlying lease. A regular `device_open` session alone does not establish
a SimLock lease. A device from a `simlock-` host in `device_list` is that
integration. If unavailable, report interactive disposable verification blocked;
do not combine an unrelated CLI lease with a panel session or substitute another
driver. Apply the [run ownership guard](workflow.md#choose-the-route-before-acquiring)
before reusing, renewing, cancelling or releasing anything.

Project suites may use their supported SimLock route independently of panel
support, under [verification and hold scope](workflow.md#choose-the-route-before-acquiring).

## Connection setup

For authorized adoption, discover the host's supported SimLock connection/setup
and confirm the Device panel and pinned agent-device command refer to the
granted device and lease. Do not switch device sets just to make an ordinary
panel discover a private device, or overwrite a T3-provided agent-device
connection. Missing host support blocks that integration, not independent build
work.

## Recovery and stop

Quote the error and follow its recovery advice once through supported tools and
the returned driver, including any requested diagnostic. If that still fails,
report the blocker and stop work dependent on that route, subject to the
[pre-grant recovery cases](workflow.md#when-a-session-fails). Preserve T3's
connection, session and install directory. Do not open a second lease or use an
alternate driver as a workaround. Record diagnostics unavailable through that
route. A task's stricter retry limit or prohibition on another open remains binding.

Worker recovery alone does not prove the panel works. When no supported safe
metadata check is available, report panel state as unverified; do not invent a
probe or retry a prohibited open. This does not add a metadata reconfirmation
gate to independent supported build/test work. Keep required visual proof
pending until the supported interactive route can provide it.

Use [bounded failure diagnostics](workflow.md#when-a-session-fails) and
[ownership-checked teardown](workflow.md#finish-or-retain). For qualifying iOS
boot failures, the specialized [break-glass procedure](break-glass.md) retains
its coordinated T3-wide holds and restart limits.
